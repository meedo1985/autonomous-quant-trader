**A1. AGREE.** The backward walk in `src/aqt/backtest/costs.py:506-510` stops at the first hole, and line 512 only raises when fewer than three bars remain. With three or more post-gap bars the estimator silently restarts from a two-return sample standard deviation, and the seed for every later decision is permanently re-anchored at the hole. My hand trace of Astra's scenario:

| Case | Returns used | sigma, bps | Slippage, bps |
|---|---|---|---|
| Complete history, decision hour 174 | 173 | 299.03 | 14.95 |
| Hour 170 removed | 2 | 0 | 1.00 |

The bias is anti-conservative: after every real Binance outage, costs collapse to the 1 bp floor and recover only as the post-gap sample grows. Constitution section 6 says outages are untradeable and forbids silent deletion; discarding all pre-gap estimator state is a policy nobody authorized. Three things compound it. The policy is absent from the six documented assumptions in the local report. The report's claim at `review/task3/LOCAL_REPORT.md:66` that nothing is "dropped behind the caller" is contradicted by this behaviour. The test named for hole truncation at `tests/unit/test_cost_model.py:505` only exercises the fewer-than-three case, so its name gives false assurance. The single mitigating fact Astra omitted: `TradeCost.returns_used` does expose the truncated count, so the reset is observable, but nothing distinguishes a hole from the series start.

Astra's proposed correction needs refinement. Because the look-back extends to the series start, a literal "reject any historical gap" would make every decision after a 2018 outage fail forever. The viable options are: carry the EWMA state across the hole with missing returns simply unobserved; reset but require a declared warm-up before the next tradeable decision; or raise and let orchestration mark a bounded post-gap window untradeable. Choosing among them is a scientific-owner decision under the Constitution, not an AI decision. It does not require amending the frozen spec, since the spec is silent, but the chosen rule must be written down before the backtester code hash is bound. Add a regression with enough post-gap bars for whichever rule is chosen.

**A2. PARTIAL.** Confirmed from code: line 413 multiplies `delay_bars` by `series.interval`, so a daily series delays the fill by one day, and the entry at line 395 performs no interval check. The zero-delay path accepts a daily series too, which Astra did not mention. Downgraded from blocker because the only composed path, `trade_cost`, rejects non-hourly bars through the contiguity check at lines 266-272, no consumer of the bare resolver exists yet, and the bar-series type is interval-generic by Task 2 design. Minimal fix: raise at resolver entry when the series interval differs from the frozen hour, plus one test mirroring the existing returns rejection test at line 128. No scientific content; ordinary code review suffices. Optional: the resolver accepts any non-negative delay while multipliers are a closed set, and an existing test relies on a two-bar delay, so closing the delay set is a separate choice.

**A3. AGREE as a question.** Line 307 seeds with a centered sample variance while line 310 recurses on uncentered squares. Astra's constant-return figures are exact: sigma is 0 at 168 returns, 6.4167 at 169, and 70.711 at 336, matching the closed forms 100 times the square root of one minus the decay, and 100 times the square root of one half. This is a seam between two conventions, not an error in either. On real hourly crypto data the mean return is roughly 0.7 bps against a sigma near 80 bps, so the uncentered inflation is about 0.003 bps and immaterial to slippage. The constant-return path is pathological. What makes it process-blocking is that the convention is undeclared and must be consistent with other consumers, which is my first new issue. Log returns are correctly supported by the feature factory spec and are not a defect.

**A4. AGREE, LOW.** At line 364 the product of notional and total basis points overflows before division. A notional of 1e308 with 17 bps of total cost yields infinity, and any notional above about 1e307 does. Fix: divide first, then reject a non-finite result. Note that reordering changes last-ulp rounding on ordinary inputs, so it should land before any oracle values are frozen under Constitution section 16.

## New material issues and authority

1. **MEDIUM, cross-module estimator consistency.** The cost model hard-codes a private "EWMA 168h" estimator with four private conventions: log returns, zero-mean recursion, a 168-sample seed, and gap reset. The same estimator name appears in the protocol as the target normalisation at `protocols/protocol_v1.yaml:104-108`, the default sizing estimator at lines 115-121, and the feature at `specs/FEATURE_FACTORY_v1.md:29`. If the feature factory later uses a library EWMA with different adjustment or NaN handling, cost sigma and sizing sigma will diverge for the same bar and both feed promotion statistics. Disposition needed from the scientific owner: one shared implementation, or a written equivalence rule, before the feature task starts.
2. **LOW, reporting overstatement.** The module docstring at `src/aqt/backtest/costs.py:3` claims the spec is implemented "exactly and nothing else" while making at least five undeclared choices, and the report omits the gap policy as noted under A1. Documentation-only fix after the A1 disposition.
3. **LOW, delay-stress sigma timing.** Under delay stress the implementation keeps the decision-time sigma, and the test at `tests/unit/test_cost_model.py:461` locks that in. The spec's "apply the same cost model" does not say whether sigma is evaluated at the decision or at the delayed fill. Defensible as built, but it should be declared alongside the A3 convention.
4. **LOW, non-material, Task 4 caution.** Each `trade_cost` call recomputes returns and the full EWMA path from the series start, so hourly decisions over eight years of data are quadratic in history. The series-level function and `per_side_cost_bps` already allow a single pass; the backtester design should use them.

Authority summary: A1, A3, issues 1 and 3 need a human scientific disposition and a written record; none require amending a frozen artifact because the specs are silent. A2, A4 and issue 2 are ordinary code and documentation fixes that still pass through the normal review gates. Nothing here is an automatic edit, and the frozen artifacts were not touched.
