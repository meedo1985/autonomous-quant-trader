Verdict: **SOUND WITH FIXES**

Binding one method V, with the same code and runtime for calibration and real evaluation, does remove DS7-1 and DS7-3, and the replicate-Sharpe part of DS7-2: there is no fast/exact pair left whose labels could disagree. The reading of the Annex B §2.3 "fsum" sentence is defensible, but it should be recorded as an explicit interpretation.

Centring uses the fsum mean, as Annex B requires. `S* = (mean° + μ)/sd°` is the decided identity (Annex B §2.3, FB2 §2(a)), and the shared variance matches rule 5's "one matrix suffices". For the owner:
1. Using one fast calculation (V) for both the test runs and the real evaluation is a sound fix: no question remains about whether a fast version matches a slow one.
2. Two things must be fixed first. V must refuse exactly-flat resampled columns, as the decided rule requires. The computer settings that change the last digits (thread count, processor kernel) must be pinned, and checked automatically on every run.
3. Your decision also confirms how one sentence of Annex B is read. The fsum rule covers only the averages taken across the 2,000 replicates, not the per-replicate Sharpe. The question you are asked should say this plainly.
